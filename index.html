Overview

Machine learning and AI are increasingly influencing how compilers, runtime systems, and computer architectures are designed, optimized, and used. Learned techniques can replace or complement hand-designed heuristics, guide complex optimization decisions, support adaptive execution, and help researchers and developers explore increasingly large design spaces.

At the same time, AI is changing the workflow through which compiler and systems technologies are developed. Learning-based tools can assist with performance analysis, optimization discovery, autotuning, debugging, and experimental exploration while remaining grounded in compiler analyses, system measurements, and correctness constraints.

The Learning-Augmented Compilers & Systems (LACS) workshop brings together researchers and practitioners working at the intersection of:

  • Machine learning and artificial intelligence
  • Compilers and programming systems
  • Runtime and operating systems
  • Computer architecture and hardware
  • Performance engineering and optimization
LACS provides a forum for sharing ongoing research, early results, practical experiences, and forward-looking ideas about how learning can augment compiler and systems technologies.

TinyVortex: A Learning-Guided Kernel Scheduling Engine for Configurable SIMT GPU Co-Design Space Exploration

Abstract: Tensor compilers typically optimize kernels for fixed hardware targets, overlooking opportunities for joint hardware–software design-space exploration. To this end, we present TinyVortex, an open-source fork of the tinygrad Tensor compiler targeting the configurable RISC-V Vortex GPGPU as the backend. TinyVortex enables end-to-end PyTorch-like Tensor program execution, Vortex C++ kernel generation, and performance evaluation across various GPU microarchitectural configurations across the SIMT hierarchy (threads/warps/issue-width/cores). Building on this infrastructure, we introduce a learning-guided autotuning framework that jointly explores kernel scheduling decisions and hardware parameters, which we currently prototype using cycle-level simulation. Preliminary evaluations demonstrate 1.13x and 2.97x geometric-mean speedups over default kernel rendering schedules for vector addition and SGEMM, respectively, highlighting the potential of configuration-aware compilation for GPU hardware–software co-design.

ProfileWeaver: Cost-Aware Profiler AI Harness for Automated Performance Analysis and Optimization of HPC Applications

Abstract: We study optimizers for constrained layers that consume the gradient at the constrained output and update the underlying parameters directly. For a doubly stochastic routing block parameterized by Sinkhorn iterations, training under such an optimizer leaves the score-to-router backward graph with no registered consumer. The runtime cannot discover this, because which gradients each optimizer consumes is recorded nowhere in the graph. We propose gradient-consumer declarations and dead-Jacobian elimination, which let the runtime skip building backward graphs that nothing will read. On our routing workload, the declaration cuts retained autograd state from 82 tensors to one per router; under torch.compile, the differentiated router remains 2.2× slower than the primal path and still retains its backward state. With the optimizer held identical and parameter updates numerically unchanged, eliminating the dead graph makes a full training step 6.7% faster. The optimizer’s own solves are small and dispatch-bound; batching them across routers and compiling the batched program shifts the lowest-latency execution from CPU to GPU as the number of routers grows, and a two-parameter cost model fitted per execution selects the fastest one at every held-out batch size.

Jason Cong 		UCLA
Compiling Layout Transformations for NPUs and FPGAs

Abstract: Efficient execution on NPUs and FPGAs requires reconciling producer and consumer access patterns while sustaining parallelism and avoiding memory-bank conflicts. This talk presents our work on compiling layout transformations, from bit-level stream permutations to closed-form mixed-radix swizzles, with applications to streaming FFTs and NPU data movement.
We then examine the challenges of realizing these transformations through existing HLS tools. We share lessons from using LLM agents to optimize HLS source code and refine generated RTL, highlighting performance limitations and correctness failures. These experiences motivated an MLIR agent dialect for contract-guided RTL refinement that makes compiler-derived goals, permitted transformations, and validation conditions explicit. We discuss how mathematical layout models, deterministic compilation, and LLM agents can work together to produce efficient hardware.

Call for Participation

We invite submissions on learning-augmented compilers and systems, including new techniques, empirical studies, work in progress, practical experiences, open challenges, and emerging research directions. We are particularly interested in work that applies machine learning or AI to improve:
  • Compiler and system decisions
  • Optimization and development workflows
  • Runtime adaptation
  • Performance analysis
  • Hardware–software co-design
  • The infrastructure and methodology needed to evaluate learning-augmented systems
The themes below illustrate the scope of the workshop rather than define strict boundaries. We welcome interdisciplinary work that combines ideas from compilers, systems, architecture, programming languages, machine learning, and performance engineering. Submissions need not fit neatly into one category. We encourage authors to submit bold, unconventional, and high-risk ideas that could open new directions for learning-augmented compilers and systems.

  • Learned cost models and optimization heuristics
  • Optimization phase ordering and pass selection
  • Register allocation and instruction scheduling
  • Search-space exploration and autotuning

  • AI-assisted optimization discovery & design-space exploration

  • Energy-, thermal-, and power-aware optimization

Learning for ML Systems and Emerging Workloads

Data, Infrastructure, Evaluation, and Reproducibility

We Particularly Encourage

LACS is intended to promote open technical discussion, including discussion of approaches that did not work as expected. We particularly encourage submissions presenting:
  • Negative results and carefully analyzed failed approaches
  • Lessons learned from research or deployment
  • Unexpected empirical observations
  • Reproducibility and replication studies
  • Comparisons showing when traditional heuristics remain preferable
  • Industrial experiences and deployment challenges
  • Preliminary results and work in progress
  • New datasets, benchmarks, tools, and evaluation methodologies
  • Open research questions and community challenges
  • Bold or unconventional ideas that challenge existing assumptions
A learned method does not need to outperform every existing approach to provide a valuable contribution. Well-designed studies that identify limitations, tradeoffs, failure modes, or conditions under which an approach succeeds or fails are strongly encouraged.
